# PROJECT_STATE — точка входа для агентов

Короткая сводка. Подробности — в отдельных файлах, они и есть источник правды. Обновляется при каждом заметном изменении состояния прода.

Обновлено: 23.08.2026. HEAD main: `87d21a5`.

## Продукт

«Оборот» — B2B SaaS для fashion-брендов: остатки, оборачиваемость, рекомендации «что заказать» с разбивкой по размерам, заказы на производство, бюджет закупки, прогноз, уценка. Источник данных — МойСклад (JSON API 1.2), есть демо-режим на синтетическом бренде.

## Архитектура

FastAPI и SQLAlchemy 2 (SQLite в dev, Postgres в prod через `DATABASE_URL`), Jinja2 и vanilla JS без сборки, APScheduler (ежедневный синк 06:00 МСК), Telegram-уведомления. Подробно — `ARCHITECTURE.md`, бизнес-правила — `BUSINESS_LOGIC.md`.

## Известные риски

Главный операционный риск — ручной деплой: крупное перемещение файлов опаснее самого долга, пока деплой не автоматизирован. Порядок должен быть такой: сначала деплой, потом каркас. Остальное — `TECH_DEBT.md`.

Роли агентов разделены владельцем: Claude — единственный исполнитель, Codex —
только reviewer. Прямой канал через одни комментарии Issue #2 оказался
ненадёжным: cached preview мог быть устаревшим, а комментарий не пробуждал
второго агента.

В ветке протокола подготовлена событийная автоматика GitHub Actions: новый SHA
Claude немедленно запускает read-only ревью Codex; `REQUEST_CHANGES` запускает
Claude; watchdog восстанавливает потерянную передачу. До merge workflow в
`main`, добавления `OPENAI_API_KEY`/`ANTHROPIC_API_KEY` в Actions Secrets и
успешного сквозного теста состояние канала остаётся `DEGRADED`.
