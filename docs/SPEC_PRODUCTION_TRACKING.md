# Спецификация: раздел «Производство» (PROD-1)

Дата: 17.11.2026. Автор: Claude (по решению Влада 17.11 спецификации пишет Claude).
Образец: «Реестр тиражей Chernim Cherno» (артефакт на базе Claude, 12.11.2026).

## Зачем

Человек, который шьёт одежду, должен видеть в одном месте, где сейчас каждый
запуск и когда он будет на складе, сравнивать это с планом и вовремя замечать
опоздания. Сейчас этого нет: «Поставки» планируют метраж ткани и не связаны с
заказами, а у заказа есть только статусы «черновик / в производстве / принят».

## Решения Влада 17.11.2026

1. Запуск в «Производстве» это заказ на производство из «Заказа». Отправленный
   заказ сам появляется в разделе. Отдельной сущности «партия» нет (снимает
   изоляцию D-50/SUPPLY от заказов).
2. Первая версия: только ход производства и сроки. Денег (счета, предоплаты,
   календарь оплат) в разделе нет.
3. Всё лишнее из «Поставок» убрать: метраж, материалы, плановые партии,
   предпросмотр Google-таблицы.
4. Спецификации пишет Claude (изменение роли D-2 для этой работы).

## Что видит человек

Страница `/production`, пункт меню «Производство» на месте «Поставок».
`/supply` перенаправляет на `/production`.

**Сводка сверху (одна строка):** в работе N запусков на X шт; опаздывают N;
приедет за 14 дней X шт; принято за 30 дней X шт.

**Фильтр по цеху** (чипы) и переключатель вида «Доска / Список».

**Доска**, четыре колонки, одинаковые для всех цехов:

| Колонка | Что в ней |
|---|---|
| Заказано | отправлен в производство, отметок этапов нет |
| В работе | отмечен хотя бы один этап, кроме последнего |
| Сдано, едет | отмечен последний этап цеха или есть частичная приёмка |
| Принято | принят на склад за последние 30 дней |

Внутри колонки карточки идут по дате «на складе»: что раньше, то выше.

**Карточка запуска:** название заказа, модели и штуки, цех, полоска этапов
цеха с текущим этапом и датой, дата «на складе» (точная, «≈» или «опаздывает
на N дн»), отклонение от плана, «сдано 37 из 44», «принято 20 из 44».
Кнопка «→ <следующий этап>» отмечает его сегодняшним числом одним нажатием.

**Список** (на телефоне по умолчанию): те же карточки одной лентой по дате.

**Окно запуска:** позиции с размерами, лента этапов с датами, кто и когда
отметил, заметки, отметка этапа с выбором даты, количества (для последнего
этапа, сдача частями) и заметки, отмена своей ошибочной отметки, приёмка по
позициям (существующий `POST /api/orders/{id}/receipts`) и «Принят целиком»
(существующий переход статуса).

**Цеха: скорость** (таблица под доской): по каждому цеху завершённых запусков,
медиана «заказ → склад», доля пришедших не позже плана, медиана от каждого
этапа до склада, сколько сейчас в работе и сколько опаздывают.

**Этапы цеха:** у каждого цеха свой список (до 8 этапов). Шаблоны «Свой пошив»
(Ткань у цеха, Крой, Пошив, Сдано цехом) и «Под ключ» (Производство, Проверка,
Отправлено). Названия можно менять, этапы добавлять. Удалить этап, по которому
уже есть отметки, нельзя.

## Дата «на складе» (детерминированный расчёт, без модели)

Прибытие запуска: дата первой приёмки с количеством больше нуля (ручной или из
МойСклада), иначе дата перевода в «Принят».

Для открытого запуска берётся последняя достигнутая точка: последний отмеченный
этап по порядку цеха, а если отметок нет, дата отправки в производство.

1. **По истории цеха.** Если у этого цеха есть не меньше 2 пришедших запусков
   за 365 дней, у которых есть та же точка, дата = дата точки + медиана дней
   «точка → прибытие». Подпись «≈, по N прошлым запускам».
2. **По плану.** Иначе, если у заказа есть плановая дата прихода, она и
   показывается. Подпись «по плану».
3. **По сроку цеха.** Иначе дата отправки + срок цеха (сумма этапов цеха в
   настройках или срок организации). Подпись «≈, по сроку цеха».

Если дата прошла, а прибытия нет: «опаздывает на N дн» (красным), дата не
сдвигается и не выдумывается. Если дата позже плановой: «позже плана на N дн».

Расчёт ничего не меняет: ни «Едет», ни рекомендации, ни бюджет, ни плановую
дату заказа (формулы D-35 не затронуты).

## Автоматика

* **Принято** ставится само из приёмок МойСклада для заказов, отправленных в
  МойСклад (уже работает, D-83). Частичный приход виден сразу.
* **Этапы** в первой версии отмечаются руками: одно нажатие «следующий этап».
* Не в первой версии (записано в TECH_DEBT): перемещения МойСклада на склад
  цеха как отметка «ткань у цеха» (нужно правило, как перемещение связать с
  заказом), ссылка для цеха без аккаунта, разбор переписки с подрядчиком
  слоем ИИ (только черновики, применяет владелец, юрпроверка).

## API

* `GET  /api/production/board` всё для экрана одним ответом.
* `GET  /api/production/orders/{id}` окно запуска.
* `POST /api/production/orders/{id}/marks` отметить этап (право `orders_manage`).
* `DELETE /api/production/marks/{mark_id}` отменить отметку (`orders_manage`).
* `PUT  /api/production/stages` этапы цеха (`orders_manage`).

Все ручки фильтруют по организации; чужой заказ, отметка или цех дают 404.
Запись закрыта гейтом подписки, как любая запись рабочих данных (D-24).

## Готово, когда

1. Отправленный заказ появляется на доске в «Заказано» без действий человека.
2. Одно нажатие переводит запуск на следующий этап с сегодняшней датой.
3. Сдача частями и приёмка частями видны на карточке числами.
4. Дата «на складе» считается по правилам выше, подпись говорит, откуда она.
5. Опоздание видно на карточке и в сводке.
6. Чужая организация ничего из этого не видит и не меняет.
7. На телефоне 390 px страница не шире экрана, кнопки не меньше 44 px.
8. Пункта «Поставки» нет ни в одном меню; `/supply` ведёт на `/production`.
