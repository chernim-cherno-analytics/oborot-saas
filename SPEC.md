# SPEC — «Оборот» SaaS MVP (демо-версия)

B2B SaaS: аналитика остатков, оборачиваемости и заказов на производство для российских fashion-брендов. Данные — из МойСклад (в демо — синтетические). Это спецификация для параллельной разработки: backend-агент и frontend-агент работают по ней независимо. ОТКЛОНЯТЬСЯ ОТ КОНТРАКТОВ НЕЛЬЗЯ.

## Разделение зон

- **Backend-агент** владеет: `app/*.py`, `requirements.txt`, `run.py`. НЕ трогает `templates/`, `static/`.
- **Frontend-агент** владеет: `templates/*.html`, `static/*`. НЕ трогает `app/`.
- Легаси-код прежней системы лежит в `legacy/` — читать можно (портировать логику из `legacy/turnover.html`, `legacy/main.py`, `legacy/order.html`), менять нельзя.

## Стек

Python 3.11, FastAPI, SQLAlchemy 2 (SQLite файл `oborot.db` для демо; код писать так, чтобы переезд на Postgres был сменой DATABASE_URL), Jinja2-шаблоны, cookie-сессии (itsdangerous, подписанные), passlib bcrypt. Без JS-сборки: vanilla JS + fetch. Запуск: `python run.py` → uvicorn на 127.0.0.1:8000.

## Модель данных (SQLAlchemy, все бизнес-таблицы с org_id!)

- `users`: id, email (unique, lower), pw_hash, name, created_at
- `orgs`: id, name, plan ('trial'|'start'|'brand'|'pro', демо = 'trial'), trial_ends_at, settings_json (JSON-строка: thresholds {weak:1000, dull:2000, good:5000}, horizon_days:90, min_stock_days:3), created_at
- `memberships`: user_id, org_id, role ('owner'|'member')
- `connections`: id, org_id, kind ('moysklad'|'demo'), token_enc (Fernet, ключ из env OBOROT_SECRET), status ('active'|'error'|'pending'), config_json, last_sync_at
- `warehouses`: id, org_id, ext_id, name, active (bool, участвует в аналитике)
- `products`: id, org_id, ext_id, base_name (канон. имя без размера), size ('' если безразмерный), category, sale_price (номинал, ₽), cost_price (себестоимость, ₽), archived (bool)
- `stock_days`: org_id, product_id, date (ISO str), qty (суммарный остаток по активным складам). PK (org_id, product_id, date). Отсутствие строки на дату = не знаем; qty=0 пишется явно.
- `warehouse_stock`: org_id, product_id, warehouse_id, qty — ТЕКУЩИЙ остаток по складам
- `sales`: id, org_id, product_id, date, qty (шт, >0), revenue (₽ фактическая после скидки), is_return (bool)
- `ordered_qty`: org_id, base_name, qty — «едет к нам» (заказано на производстве)
- `production_orders`: id, org_id, name, created_at, eta_date, status ('draft'|'sent'), items_json (JSON: [{base_name, qty, sizes:{size:qty}, cost}])

## Бизнес-логика (портировать из legacy, формулы проверены на реальном бренде)

Аналитика считается по **базовому имени** (base_name), размеры — детализация. Все метрики за скользящие 365 дней:

- `dis` — «дней в стоке»: число дат в stock_days за 365 дн, где qty ≥ 3 (порог из settings.min_stock_days). Честный темп: только дни, когда товар реально был в наличии.
- `cs` — текущий остаток: qty на ПОСЛЕДНЮЮ имеющуюся дату (сумма по размерам); отсутствие строки на последнюю дату = 0.
- `nq`, `nr` — нетто продано шт / нетто выручка за 365 дн (продажи минус возвраты).
- `rate` = nq/dis (шт/день, 0 если dis=0). `turnover` = nr/dis (₽/день) — ГЛАВНАЯ метрика.
- Классы оборачиваемости (цвета): <1000 «слабый» (красный), 1000–2000 «унылый» (жёлтый), 2000–5000 «хороший» (зелёный), ≥5000 «бестселлер» (тёмно-зелёный). Пороги из settings.
- `wos` (недель покрытия) = cs / (rate*7), null если rate=0.
- `stockout_date` = today + cs/rate дней (null если rate=0).
- `need` (рекомендация к заказу) = max(0, round(rate*horizon_days) − cs − ordered_qty). horizon_days=90.
- `avg_price` = nr/nq; `discount_fact` = 1 − avg_price/sale_price (цвета: ≥0.3 красный, ≥0.15 жёлтый, ≤0 зелёный).
- Размерная сетка позиции = union(размеры текущего стока, размеры продаж за 365 дн) — НЕЛЬЗЯ брать только сток (распроданные размеры выпадут). Разбивка заказа по размерам — пропорционально нетто-продажам размеров за 365 дн, largest remainder.
- Прибыль с заказа = (avg_price − cost_price) × qty.

## HTTP-контракты

### Страницы (GET, Jinja2; без авторизации → redirect /login)
- `/login`, `/register` — формы (POST туда же; после успеха redirect `/`)
- `/logout` (POST)
- `/onboarding` — мастер подключения (для орг без активного connection): шаг 1 выбор источника (МойСклад токен | Демо-данные), шаг 2 (для демо мгновенно) — прогресс, redirect `/`
- `/` — Дашборд «Показатели»
- `/replenish` — «Что заказать» (главная рабочая таблица)
- `/turnover` — «Оборачиваемость»
- `/stocks` — «Остатки» по складам
- `/orders` — «Заказы на производство» (список + создание из /replenish)
- `/settings` — настройки (организация, пороги, склады, тариф, команда)

Каждая страница рендерится через `base.html` (frontend), которому передаётся: `user` (name,email), `org` (name,plan,trial_ends_at), `active` (ключ пункта меню), `page_title`.

### JSON API (все под сессией, все данные только текущей org!)
- `GET /api/summary` → `{stock_value_retail, stock_value_cost, stock_units, positions, turnover_total, sold_30d_qty, sold_30d_rev, alerts:[{type:'stockout'|'overstock'|'no_sales', base_name, text, severity:'red'|'yellow'}], classes:{weak:n, dull:n, good:n, best:n}, top:[{base_name, turnover}...5], categories:[{name, stock_units, stock_value, share}]}`
- `GET /api/replenish` → `{horizon_days, items:[{base_name, category, cls:'weak'|'dull'|'good'|'best', turnover, rate, cs, ordered, wos, stockout_date, need, sizes:{size:{stock, sold365, rec}}, avg_price, cost_price, profit_potential}]}` — отсортировано по turnover desc, только need>0 в основном списке, остальные отдельным массивом `excluded:[{base_name, reason}]`
- `GET /api/turnover` → `{items:[{base_name, category, dis, cs, nq, nr, turnover, cls, avg_price, sale_price, discount_fact, wos, stockout_date}]}` sorted turnover desc
- `GET /api/stocks` → `{warehouses:[{id,name}], items:[{base_name, category, per_wh:[qty...], total, sizes:[{size, per_wh:[...], total}]}]}`
- `GET /api/orders`, `POST /api/orders` (body {name, eta_date, items}), `GET /api/orders/{id}`
- `POST /api/ordered` (body {base_name, qty}) — ручное «едет к нам»
- `GET /api/settings`, `POST /api/settings` (thresholds, horizon), `POST /api/warehouses/{id}/toggle`
- `POST /api/connect/demo` — создаёт demo-connection, сеет демо-данные, redirect-ready `{ok:true}`
- `POST /api/connect/moysklad` (body {token}) — сохраняет шифрованный токен, status='pending', возвращает `{ok:true, note:'Синхронизация начнётся автоматически'}` (реальный синк вне демо-скоупа, но клиент МС с rate-limiter должен быть написан в `app/ms_client.py`: 45 req/3 сек, ≤5 параллельных, retry на 429 по X-Lognex-Retry-TimeInterval)

### Демо-данные (app/demo_seed.py)
Синтетический бренд уровня Chernim Cherno: ~55 базовых позиций в категориях (Худи и свитшоты, Футболки, Рубашки, Брюки, Верхняя одежда, Платья, Сумки, Украшения, Аксессуары), реалистичные русские названия («Худи \"Скетч\"», «Серьга 12 мм»...), размеры S/M/L/XL у одежды, One Size у украшений. 400 дней истории stock_days и sales: сезонность (зимой курки/худи растут), недельный цикл (пт-сб пик), 5–6 бестселлеров (turnover ≥5000), хвост слабых, 3–4 позиции распроданы в ноль (cs=0, но продажи были — для проверки need>0 у отсутствующих), 2 позиции без продаж (неликвид для алертов). 3 склада: «Магазин на Гороховой» неактуально — назвать нейтрально: «Флагман», «ТЦ Атриум», «Интернет-магазин». Цены 2 000–45 000 ₽, себес ~40% от цены. Генерация ДЕТЕРМИНИРОВАННАЯ (random.seed(42)), суммарно ~150–250к строк максимум, сеется за <30 сек.

## Дизайн (frontend) — оболочка в духе МойСклад

Референс — интерфейс moysklad.ru (веб-приложение): плотный деловой UI, СВЕТЛАЯ тема. НЕ копировать пиксельно, взять паттерны:

- **Раскладка:** узкий тёмно-синий (#1F2B3D или близкий) левый сайдбар ~220px с вертикальным меню (иконки+подписи, белый текст, активный пункт — светлый фон-плашка/акцент); белая рабочая область; верхняя панель страницы: h1 слева, справа — имя организации, тариф-бейдж, меню пользователя.
- **Меню:** Показатели (/), Что заказать (/replenish), Оборачиваемость (/turnover), Остатки (/stocks), Заказы на производство (/orders), Настройки (/settings). Внизу сайдбара — логотип «Оборот» + версия.
- **Таблицы:** плотные (padding 8–10px), sticky-заголовок, границы-волосок #e5e7eb, ховер строки, сортировка кликом по заголовку, пословный поиск сверху (как в legacy: query.split(/\s+/).every(w=>name.includes(w))), фильтры-кнопки категорий. Числа — моноширинная выравнивание вправо, тысячи с пробелом, ₽ без копеек.
- **Цвета классов оборачиваемости:** слабый #e5484d, унылый #f5a623 (текст читаемый), хороший #4cbb17, бестселлер #1a7a2e. Использовать точками-индикаторами и бейджами, не заливкой всей строки.
- **Карточки-метрики:** белые, border #e5e7eb, radius 8px, лёгкая тень; крупное число + подпись + опц. дельта.
- **Акцентный цвет действий:** синий #2563eb (кнопки, ссылки). Кнопка primary — синяя заливка; secondary — белая с бордером.
- **Шрифт:** системный стек (-apple-system, Segoe UI, Roboto). Без веб-фонтов.
- **Демо-бейдж:** если org.plan=='trial' — тонкая жёлтая полоска под шапкой: «Демо-режим: показаны синтетические данные. Триал до {дата}».
- Страницы `/login`,`/register`,`/onboarding` — без сайдбара: центрированная карточка на светло-сером фоне, логотип «Оборот».
- Иконки — inline SVG (простые, stroke 1.5–2, вроде Lucide), нарисовать руками несколько штук, без CDN-зависимостей. Логотип «Оборот» — простой словесный знак + круговая стрелка, inline SVG.
- JS: каждый экран тянет свой /api/* fetch'ем и рендерит таблицу; общие утилиты в `static/app.js` (fmt чисел, sort, поиск, debounce). Состояние сортировки/фильтров — в памяти страницы.

### Ключевые экраны
1. **Показатели (/)** — карточки: деньги в стоке (по себесу и по рознице), штук на складе, продано за 30 дн (₽/шт), позиций в ассортименте; блок «Требуют внимания» (алерты: скоро стокаут у бестселлера — красный, неликвид >120 дн без продаж — жёлтый); мини-таблица топ-5 по оборачиваемости; распределение классов (4 цветные плашки с числом позиций); категории с долями стока.
2. **Что заказать (/replenish)** — ГЛАВНЫЙ экран продукта (паттерн action-table мировых лидеров): таблица потребности: позиция, класс (точка), оборачиваемость ₽/день, остаток, «едет», недель покрытия, дата стокаута, **рекомендуем заказать (шт)** — жирным, раскрытие строки → разбивка по размерам (сток/продажи/рекомендация, инпуты правки); сверху сводка: «Рекомендуем заказать N позиций, M шт, ~X ₽ себестоимости, ожидаемая выручка Y ₽»; кнопка «Создать заказ на производство» → POST /api/orders из отмеченных чекбоксами строк (по умолчанию все), затем redirect /orders.
3. **Оборачиваемость (/turnover)** — таблица всех позиций: класс, дней в стоке, продано шт/₽ нетто, оборачиваемость (сортировка по умолчанию), средняя цена vs номинал, факт. скидка (цвет), остаток, покрытие. Фильтры категорий + поиск + переключатель «показать архивные».
4. **Остатки (/stocks)** — колонки по складам, раскрытие по размерам, красная метка «нет на складе X».
5. **Заказы (/orders)** — список карточек заказов (имя, дата, ETA, позиций/шт/себес, статус), клик → детальная таблица позиций с размерами; печать (window.print, аккуратный print CSS).
6. **Настройки (/settings)** — секции: Организация (имя, тариф с описанием лимитов, кнопка «Сменить тариф» — заглушка), Пороги оборачиваемости (4 инпута + описание), Горизонт заказа (дней), Склады (галочки активности), Подключение (статус источника данных; для МС — поле токена), Команда (список участников, приглашение — заглушка).

## Definition of Done
- `python run.py` поднимает сервер; регистрация → онбординг → «Демо-данные» → все 6 экранов работают на демо-данных без JS-ошибок.
- Изоляция тенантов: все запросы фильтруют org_id из сессии; чужие данные недоступны (проверить вторым аккаунтом).
- Токены МС шифруются Fernet; секрет из env, дефолт для дев-режима.
- Пароли bcrypt; сессионная кука HttpOnly, SameSite=Lax, подписанная.
