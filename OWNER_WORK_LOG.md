# Журнал работ для владельца

Это постоянный журнал простым русским языком: что сделано, что это меняет и что
осталось. Он для человека, а не для машины. Технические подробности живут в
других файлах (`AGENTS.md`, `AGENT_AUTOMATION.md`, `DECISIONS.md`), здесь —
понятный пересказ.

Правила ведения:

* Claude обновляет этот файл после каждого законченного блока работы.
* Записи не переписываются задним числом. Ошиблись — новая запись с поправкой.
* Новые записи добавляются сверху, сразу под этим заголовком.
* Каждая запись идёт по обязательному шаблону из шести пунктов (ниже).
* Термин поясняется сразу, в скобках, простыми словами.
* Голые номера коммитов и служебные слова вроде `PUSHED` в основной текст не
  идут. Ссылки и номера — в конце записи, отдельным пунктом «Техническая
  справка», для тех, кому нужно проверить.

Шаблон записи:

```
## <дата> — <задача одной строкой>

**Какие новые возможности добавили**
**Что исправили**
**Что это меняет для владельца**
**Как проверили**
**Что осталось / нужно ли решение владельца**
**Техническая справка** (необязательно: ссылки, номера коммитов, файлы)
```

Параллельный журнал второго агента (Codex) называется `PROJECT_WORK_LOG.md` и
живёт в его собственном проекте ChatGPT — подробности в `AGENTS.md`, раздел 6.

## 23.08.2026 — настроен канал связи между двумя агентами

**Какие новые возможности добавили**

Связка из двух помощников теперь работает по кругу и без вашего участия на
каждом шаге. Claude пишет код, второй помощник (Codex) его проверяет, Claude
исправляет замечания, и круг повторяется, пока замечаний не останется.

*GitHub как техническая почта.* Все сообщения между помощниками — заявки на
работу, замечания ревью и отчёты — лежат в самом GitHub: в Pull Request
(предложение изменений, которое вы одобряете перед тем, как оно попадёт в
основную версию) и в постоянно открытом обсуждении Issue №2. Это сделано ради
надёжности: домашний компьютер может уснуть, перезагрузиться и всё забыть, а
GitHub не забудет ничего. После пробуждения работа продолжается ровно с того
места, где прервалась.

*Проверку кода делает Codex.* Он подключён к репозиторию (хранилищу кода) и
читает изменения сам. Он работает только на чтение: свой код в проект он не
пишет и ничего не меняет — только находит проблемы и объясняет их. За это уже
заплачено вашей подпиской.

*Исправления делает Claude на вашем компьютере.* Специальная программа-диспетчер
(`tools/agent-bridge`) примерно раз в минуту заглядывает в GitHub, находит
свежие замечания, зовёт локального Claude, прогоняет тесты, сохраняет
исправления и отчитывается в Pull Request. За это тоже уже заплачено подпиской
Claude Max.

*Опрос без ключей и без дополнительных счетов.* Раньше эта же схема жила внутри
GitHub и на каждый круг вызывала платные программные интерфейсы OpenAI и
Anthropic — то есть вы платили второй раз за то, что уже оплачено подписками.
Теперь платных ключей в проекте нет вообще: доступ к GitHub берётся из вашей
уже выполненной авторизации, доступ к модели — из уже авторизованного Claude на
вашем компьютере. Ключей нет, значит, их нельзя случайно потерять.

*Явное пробуждение проверяющего.* После каждого сохранённого исправления
диспетчер отдельным сообщением просит: «@codex review» — то есть «посмотри
новую версию». Так пришлось сделать по наблюдению: 23.08.2026 новая версия кода
сама проверку не запустила, а такая просьба запустила сразу. Без просьбы круг
молча замирал бы, и это выглядело бы как «всё в порядке, замечаний нет».

*Защита от бесконечного круга.* Два помощника, которые будят друг друга, — это
риск бесконечной переписки и бессмысленной траты сил. Ограничения зашиты в саму
программу, а не только в инструкцию: не больше трёх попыток на одну версию кода,
дальше работа останавливается и зовёт человека; вливать изменения в основную
версию автоматика не имеет права никогда — это только ваше решение; переписывать
историю проекта нельзя; собственные файлы автоматики и настройки GitHub правки
по ревью не затрагивают (автоматика не чинит сама себя вслепую); повторные
одинаковые сообщения в переписку не попадают. Отдельный сторож раз в час
проверяет, не зависла ли проверка дольше полутора часов, и пишет об этом —
обычная причина такого молчания в том, что домашний компьютер спит.

*Закреплена модель исполнителя.* Основная — `opus`, запасная — `fable`
(«модель» — конкретная версия ИИ, которая пишет код; «запасная» включается
сама, если основная перегружена). Обе видны в проверке состояния и в отчёте о
состоянии, обе можно поменять в настройках.

*Появился этот журнал.* Раньше понять, что происходит, можно было только из
переписки в чате или из технической ленты в GitHub — первое исчезает вместе с
чатом, второе написано для машины. Теперь после каждого законченного блока
работы Claude добавляет сюда запись по одному и тому же шаблону. Второй
помощник ведёт такой же журнал у себя и той же понятной сводкой отвечает вам в
переписке. Техническая лента в GitHub при этом остаётся как была — она нужна
самим помощникам и сторожу.

**Что исправили**

Раньше настройка «какой моделью работать» была пустой и означала «той, что
сейчас выбрана в Claude Code». Достаточно было один раз переключить модель в
обычной беседе ради другой задачи — и фоновые исправления молча пошли бы другой
моделью, а по журналу это невозможно было отличить. Теперь модель записана явно
и видна в двух местах. Запасной модели не было вовсе: перегрузка основной
выглядела как обычная ошибка, съедала одну попытку из трёх и создавала
впечатление, что исправить замечание невозможно.

Сама схема связи пережила пять кругов проверок и правок. Из существенного:
проверка версии кода делалась по ненадёжному признаку — GitHub переносит старые
замечания на новую версию, и старая проверка выглядела как новая, из-за чего
попытки тратились впустую; тесты у автоматики запускались не тем интерпретатором
(программой, которая исполняет код), из-за чего любая правка выглядела как
«сломала тесты»; настройки, проверенные при установке, до фоновой задачи не
доезжали — она читала не тот файл; замечания, не поместившиеся в один заход,
терялись, а теперь приезжают следующим кругом и ровно один раз.

**Что это меняет для владельца**

Вам не нужно вручную пересказывать замечания одного помощника другому и следить
за очередью. Ваша роль остаётся в двух точках, и обе — решающие: вы ставите
задачу и вы одобряете слияние с основной версией. Автоматика не сливает ничего
и никогда, даже когда оба помощника согласны между собой.

Дополнительных денег схема не стоит: обе стороны круга уже оплачены подписками,
платные ключи из проекта убраны.

Пока канал считается «работает не полностью»: файлы и правила на месте, но
фоновая задача на вашем компьютере ещё не установлена и полный круг вживую не
проходил. Наличие файлов работоспособность не доказывает.

**Как проверили**

Написан отдельный набор тестов именно на автоматику — 143 проверки, все
проходят. Проверяются те места, где ошибка не падает, а притворяется тишиной:
потерянные замечания, не отправленный отчёт, старая проверка, выданная за новую,
дубли в переписке, чужой интерпретатор тестов, настройки, не доехавшие до
фоновой задачи, и теперь — модель исполнителя и шаблон этого журнала (чтобы
запись со временем не превратилась обратно в протокол).

Тесты автоматики не трогают ни ваш продукт, ни настоящую фоновую задачу на
компьютере: всё проверяется на временных копиях. Продуктовый код в этой работе
не менялся вообще.

Отдельно проверено вручную и записано как наблюдение: новая версия кода сама
проверку Codex не запускает, а просьба «@codex review» запускает.

**Что осталось / нужно ли решение владельца**

Осталось одно, и без вас это сделать нельзя: установить фоновую задачу на вашем
компьютере (одна команда — `tools/agent-bridge/install.sh`) и провести полный
круг вживую — замечание, исправление, новая проверка. До этого канал остаётся в
состоянии «работает не полностью».

Решение владельца нужно по одному вопросу: сливать ли этот Pull Request в
основную версию. Ничего в продукте он не меняет; в нём документы, автоматика и
её тесты.
