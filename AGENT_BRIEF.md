# AGENT_BRIEF.md — операционный пакет задачи

Короткий шаблон, которым Codex ставит задачу, а Claude её забирает. Один пакет —
одна задача — один PR или один release outcome.

**Чем этот файл НЕ является.** Он не источник продуктовой истины и не заменяет
`AGENTS.md`, `DECISIONS.md` и `BUSINESS_LOGIC.md`. Brief — указатель: он говорит,
что делать в этом цикле и куда посмотреть, а не что правда про продукт. При
любом расхождении brief проигрывает: правила совместной работы, стоп-условия и
release gate — в `AGENTS.md`, решения — в `DECISIONS.md`, формулы и бизнес-правила
— в `BUSINESS_LOGIC.md`. Заполненный brief живёт в комментарии Issue координации,
а не в этом файле: здесь только шаблон.

## Шаблон

```
TASK:      P<N>-<буква> — одна фраза, один outcome.
BASE_SHA:  для пакета работы — полный 40-символьный SHA, от которого
           создаётся ветка. В пакете выпуска поля нет.
TARGET_SHA: для пакета выпуска — полный 40-символьный SHA, который
           проверяется и выпускается (коммит слияния). В пакете работы
           поля нет.
SCOPE:     что именно меняется (например: только процессная документация).
FILES:     ожидаемые файлы. Расширять — только с доказанной необходимостью,
           названной в PR.
DONE_WHEN: нумерованные проверяемые условия. Проверяемые — значит по ним видно
           «да» или «нет» без спора.
RISKS:     чем эта задача может испортить проект, включая риск разрастания diff.
LINKS:     только ссылки, нужные для ЭТОЙ задачи.
CURSOR:    id последнего координационного комментария, подтверждённого
           исполнителем пакета (или NONE).
```

## Правила заполнения

**LINKS — только релевантное.** Ссылка, которая «вообще полезна», в пакет не
идёт: каждая лишняя ссылка стоит чтения, а прочитанное лишнее вытесняет нужное.

**CURSOR — граница, подтверждённая исполнителем пакета, а не отправителем.** Это
id последнего комментария Issue координации, который сам исполнитель прочитал и
подтвердил в предыдущем цикле; позиция чтения отправителя курсором не является.
Подтверждённой границы ещё нет (новый исполнитель, первый цикл) — пишется
`CURSOR: NONE`, и тред читается с начала.

Курсор существует, чтобы не перечитывать весь тред каждый цикл: исполнитель
читает сам комментарий-курсор, весь хвост после него и адресно то, на что
ссылается пакет. Непрочитанного между курсором и текущим моментом так не
остаётся. Курсор — заявление «до сюда прочитано и учтено», поэтому двигается
только после фактического чтения.

**Пакет выпуска обязан нести `TARGET_SHA`.** У выпуска ветки нет, поэтому
`BASE_SHA` в нём не заполняется, а цель называется полным 40-символьным SHA,
выписанным в пакет буквами. Ссылка на PR или имя ветки целью не считаются:
их HEAD может сдвинуться, и тогда проверенным окажется одно, а выпущенным —
другое. Пакет без `TARGET_SHA` неполон, и выпуск по нему не начинается.
Что дальше происходит с этим SHA — release gate в `AGENTS.md` §2, шаг 9.

**Большие документы читаются адресно.** `DECISIONS.md` и `TECH_DEBT.md` — журналы
в сотни строк; в них ищется нужная запись (`rg -n 'D-35|OPS-7' DECISIONS.md
TECH_DEBT.md`), а не читается всё подряд. Это про способ чтения, а не про право
не читать: обязательный список шага 1 в `AGENTS.md` §2 и стоп-условия §3
адресным чтением не отменяются и не сокращаются.

**Один активный write lane.** Пакет работы забирается коротким CLAIM в Issue
координации до первой строки правки (`AGENTS.md` §2, шаг 2а). CLAIM, ветка и PR
относятся к одной задаче: новый outcome — новый пакет и новый CLAIM, а не
продолжение прежнего.

**Пакет выпуска забирается CLAIM без ветки** — `TARGET_SHA` и `FILES: none`, и
write lane он не занимает (`AGENTS.md` §2, шаг 2а). Понадобилась правка файла —
выпуск останавливается и заводится пакет работы по обычной форме, с веткой.

## Ревью и приёмка

Ревью — **diff-first и на точный HEAD**: проверяется опубликованный diff
названного полного SHA, а не пересказ автора и не «ветка вообще».

**Любой новый коммит в ветке обнуляет прежнее одобрение** — приёмка относилась к
тому HEAD, которого больше нет, и запрашивается заново на новом (`AGENTS.md`
§2, шаг 9).

Всё остальное про выпуск — release gate, стоп-условия, строгий CI, мандат
владельца — в `AGENTS.md`. Здесь это сознательно не пересказывается: два текста
об одном расходятся, и тогда исполняется тот, что удобнее.
