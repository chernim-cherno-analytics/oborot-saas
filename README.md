# Оборот — аналитика склада и заказов на производство для fashion-брендов

B2B SaaS: остатки, оборачиваемость, рекомендации «что заказать» с разбивкой по размерам,
заказы на производство, бюджет закупки (OTB), прогноз, рекомендации уценки.
Источник данных — МойСклад (JSON API 1.2); демо-режим с синтетическим брендом.

## Стек
FastAPI + SQLAlchemy 2 (SQLite в dev, Postgres в prod через `DATABASE_URL`),
Jinja2 + vanilla JS (без сборки), APScheduler (ежедневный синк 06:00 МСК),
Telegram-уведомления. Дизайн-система «Штаб» (тёмный сайдбар, data-first).

## Запуск (dev)
```bash
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8000
```
Регистрация → онбординг → «Демо-данные» — полный продукт на синтетике.
Подключение МойСклад: онбординг → вставить API-токен → выбрать склады → синк ~5–10 мин.

## Переменные окружения (prod)
| Переменная | Значение |
|---|---|
| `OBOROT_ENV` | `prod` (включает fail-fast секрета и Secure-куки) |
| `OBOROT_SECRET` | длинный случайный секрет (подпись сессий + шифрование токенов) |
| `DATABASE_URL` | `postgresql+psycopg://...` (dev-дефолт: sqlite `oborot.db`) |
| `SCHEDULER_ENABLED` | `1` (ежедневный синк; ставить только на ОДНОМ воркере) |
| `OBOROT_TG_BOT_TOKEN` / `OBOROT_TG_BOT_NAME` | бот для утренних дайджестов (опц.) |
| `MS_BASE_URL` | переопределение API МС (для тестов) |
| `HISTORY_DAYS` | глубина истории остатков при первичном синке (дефолт 365) |

## Важные инварианты (не ломать)
- Все бизнес-запросы фильтруются по `org_id` (мультитенантность).
- `report/stock/all` МойСклад: `moment` работает только ВНУТРИ `filter=`.
- Цены МС приходят в копейках (`/100`).
- Черновики заказов НЕ учитываются в «едет к нам» — только статус «В производстве».
- «Едет к нам» = локальный вклад (ordered_qty.qty: заказы «В производстве» без
  отправки в МС + ручные правки) + вклад МойСклад (ordered_qty.ms_qty: проведённые
  «Заказы поставщику» за окно истории, по позициям quantity − shipped; пересобирается
  каждым синком). Заказ, отправленный в МС кнопкой push-to-ms, учитывается ТОЛЬКО
  через ms_qty — статусные переходы его локальный qty не двигают (нет двойного счёта).
- Синк пишет явные нули (позиция пропала из отчёта → qty=0), продажи перезаписываются окном 3 дня.
